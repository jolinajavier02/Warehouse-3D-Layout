# Warehouse 3D Layout

Warehouse 3D Layout is a browser-based layout planner for displaying shop, path, boundary, gate, exit, restroom, and dimension data as an interactive 3D map. The app uses React, TypeScript, Vite, Three.js, and an optional Express/PostgreSQL API.

## Features

- 3D warehouse map with solid shop blocks, boundary, surface, lanes, signs, and dimension guides.
- Sidebar pages for Home, Data Governance, Layout Strategy, and Analytics.
- Data Governance upload for CSV, XLS, and XLSX files.
- Editable data table where adding, changing, or deleting rows updates the 3D map.
- Empty-data state that clears the map until new data is uploaded or entered.
- Sample CSV files stored in one source data folder.

## Requirements

- Node.js 20 or newer
- npm

PostgreSQL is optional. The client can run from local CSV/uploaded browser data without a database.

## Install

```bash
npm install
```

## Run The Website

```bash
npm run dev
```

Open the Vite client in your browser:

```text
http://localhost:5173
```

The Express API starts on:

```text
http://localhost:3001
```

## Build

## Upload Schema

CSV and Excel uploads should use these columns:

```text
id,type,name,xmin,ymin,xmax,ymax,zmin,zmax,description
```

The parser also accepts common variants such as `xMin`, `x_min`, `X Min`, and similar spacing or casing changes.

Supported `type` values:

```text
Boundary
Layout Zone
Main Aisle
Work Area
Pillar
Gate
Wall
Non-placeable Area
Shelf
Nestainer
Operation Area
Shop
Path
Dock
Rack
Office
```

For shop blocks, use `type` as `Shop`. The block size is calculated from:

```text
xmin,ymin,xmax,ymax,zmin,zmax
```

If `zmax` is empty, the app uses a default height for that item type.

## Using Data Governance

1. Open the website.
2. Go to `Data Governance`.
3. Click `Upload Data`.
4. Select a `.csv`, `.xls`, or `.xlsx` file from your computer.
5. The uploaded data appears in the table and immediately builds the 3D map.
6. Edit rows to update the map.
7. Delete rows to remove those blocks from the map.

Uploaded data is stored locally in the browser with `localStorage`, so each browser can keep its own current layout.

## Browser Notes

Chrome, Safari, and VS Code preview should render the same layout after a fresh load. If Chrome shows an older layout, clear the site data or hard refresh the page:

```text
Shift + Reload
```

or open DevTools, right-click the reload button, and choose `Empty Cache and Hard Reload`.

## Optional Database

The server can read locations from PostgreSQL when database environment variables are set. Without PostgreSQL, the client can still use the CSV files and browser uploads.

Locations table:

```sql
create table locations (
  id text primary key,
  name text not null,
  type text not null,
  x_min numeric not null,
  y_min numeric not null,
  x_max numeric not null,
  y_max numeric not null,
  z_min numeric not null,
  z_max numeric not null,
  description text
);
```

Environment options:

```text
DATABASE_URL
PGHOST
PGPORT
PGDATABASE
PGUSER
PGPASSWORD
```

## Troubleshooting

- If blocks do not appear after upload, check that the file has `id`, `type`, `name`, `xmin`, `ymin`, `xmax`, `ymax`, `zmin`, and `zmax`.
- If the map is empty, the current browser data may have no rows. Upload a data file again from Data Governance.
- If the browser shows old output, hard refresh or clear local site data.
- If a port is already in use, stop the old dev server and run `npm run dev` again.
- If `client/dist/` or `server/dist/` appears, it is generated output. Delete it when cleaning the repo, then run `npm run build` when production files are needed.
